Application information API technical guide

Use this service to get information about a specific application

Version and Status

How to use the Application information API

The Application information API is used to get detailed information about a specific application, using the application_request_id returned by the Submit an application API request.

The status of an application can currently be one of the following:

  • VALIDATING - HMLR is still processing the application, and it has not yet been added to the day list
  • VALIDATION_FAILED - The application has not been added to the day list due to errors during validation. The errors found are included in the errors section of the response
  • ACCEPTED_AWAITING_PRIORITY - The application has passed validation but has not yet been added to the day list as it is currently closed. The application will be added to the day list and moved to an ACCEPTED_PRIORITY_PROTECTED state when the day list reopens
  • ACCEPTED_PRIORITY_PROTECTED - The application has been accepted onto the day list, and has priority
  • SYSTEM_ERROR - The application has not been added to the day list due to an HMLR system error. The request should be retried, or the support team contacted
  • CANCELLED - The application has been cancelled. Further information should be available in the correspondence documents.
  • COMPLETED - The application has been completed. Further information should be available in correspondence documents and completion data. If completion data (completion_data) is not available, one of the following status messages is provided:
    • PENDING - completion data is being processed and will be available soon
    • UNAVAILABLE - a processing error has occurred, which the HMLR support team must resolve

This API will always return an HTTP 200 response for a valid request, regardless of the status of the application.

Validation rules

There are no validation rules for implementing this API.

Search reference warning

The following warnings are displayed for information purposes, when a search reference is provided, but does not match our records for the reasons below:

Warning message Reason
SEARCH_REFERENCE_DOES_NOT_MATCH “The search reference provided, at the time of submission, is not the highest priority search on the daylist." A search reference is provided, but it doesn’t match the highest priority search on record
SEARCH_REFERENCE_NOT_PROVIDED “There are official searches found on the daylist.” A search reference isn’t provided at all, but there is an active search on the daylist
SEARCH_REFERENCE_NOT_REQUIRED “The search reference provided, at the time of submission, is not a live search on the daylist.” A search reference is provided, but there is no active search on the daylist

Digital mortgage validation

Note:

Digital mortgage submissions are currently limited to:

  • integrators who already use our digital mortgage service, and their customers
  • single title charge transactions with a title scope of WHOLE

For digital mortgage applications:

  • an e-MD reference is required
  • no documents need to be attached

Digital mortgage validation error types

Error type Description
TOO_MANY_TITLES Provide an e-MD reference for single title applications only
INVALID_TRANSACTION_TYPE Provide an e-MD reference for charge transactions only
INVALID_TITLE_SCOPE Title scope must be WHOLE for the title associated with a transaction containing an e-MD reference
TOO_MANY_TRANSACTIONS_WITH_EMDREF Provide a maximum of one transaction that contains an e-MD reference
